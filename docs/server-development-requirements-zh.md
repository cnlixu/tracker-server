# 电力定位跟踪器平台开发要求

## 1. 建设目标

平台用于管理电力定位跟踪器，接收定位、时间、信号、电池和设备状态，提供实时状态、历史轨迹、离线补传、告警、短信通知和设备运维能力。

一期按 10000 台设备设计，必须保证至少 500 个设备并发连接。设备典型上报周期为 5～15 分钟，最快可配置为 5 秒；平台容量和数据库写入能力必须按最快周期、离线设备集中补传和 FOTA 后集中上线的叠加峰值设计。

## 2. 系统构成

- 设备接入服务：TCP、JT/T 808 解帧、注册鉴权、分包重组和 ACK。
- 数据处理服务：校验、标准化、幂等去重、状态计算和告警判定。
- PostgreSQL 或同等级数据库：设备、轨迹、告警、规则和审计数据。
- 管理平台：设备管理、地图、轨迹、告警、短信记录、参数和权限管理。
- 短信服务：通过可替换供应商接口发送并回写状态。
- 运维监控：连接数、吞吐、延迟、错误、数据库和短信指标。

接入服务应支持横向扩容。负载均衡必须使用四层 TCP；同一连接内的子包重组状态必须位于同一实例，或存储在共享状态服务中。

## 3. 设备通信

设备只使用裁剪版 JT/T 808-2019，具体字节定义见 `docs/protocol.md`。不再接受 `$PTRK` ASCII 和原自定义 HEX 报文。

保留消息：`0x0100/0x8100` 注册、`0x0102/0x8001` 鉴权、`0x0200/0x8001` 单条位置、`0x0704/0x8001` 离线批量位置、`0x8103/0x0001` 参数设置及 `0x8104/0x8106/0x0104` 参数查询。其他 808 功能默认不实现，新增前必须经过设备端和平台端联合评审。

`0x0100` 采用《protocol.md》定义的 EPTR 项目注册体，不使用车牌、车牌颜色等车载字段。平台应保存省域 ID、市县域 ID、制造商 ID、终端类型、能力、唯一上报周期、服务点、资产、型号、SN、IMEI、ICCID、软硬件版本、组织编码、生产批次和配置版本。允许平台修改的字段仅通过版本化 `0x8103` 整组下发；平台必须持久化期望版本、已应用版本、下发状态和最后错误，并在 PSM+ 设备下一次主动鉴权后补发，收到与下行流水号及消息 ID 匹配的成功 `0x0001` 后才标记生效。

平台要求：

- 正确处理 TCP 半包、粘包、连续报文、转义和 XOR 校验。
- 正确处理 2019 版消息头和 1023 字节标准分包。
- 单个 `0x0704` 逻辑消息支持 1～512 条位置。
- 数据库事务提交后才能发送成功 `0x8001`。
- 无法校验的帧保持静默；业务失败返回标准失败结果。
- 每次连接必须先鉴权；量产使用每设备独立鉴权码。
- ACK 丢失或连接中断时允许设备原样重传。

## 4. 数据与唯一性

JT/T 808 消息头终端手机号字段使用 SIM 对应的真实号码；IMEI 在 `0x0102` 鉴权消息体中上报并与终端手机号绑定，两者不得混用。每条位置通过自定义附加项 `0xE0` 携带 `generation_id + record_seq`。

轨迹唯一键必须为：

```text
(terminal_id, generation_id, record_seq)
```

消息流水号只有 16 位并会循环，不得用于长期去重。批次重传、部分重叠批次和服务器 ACK 丢失都必须只产生一条轨迹记录，但仍返回成功 ACK。

轨迹至少保存：设备标识、定位时间、服务器接收时间、定位有效性、经纬度、高程、速度、方向、卫星数、HDOP、信号、VBAT、电量百分比、唤醒原因、代次、记录序号和原始报文。

## 5. 设备管理

- 设备建档、批量导入、启用、停用、删除和查询。
- IMEI/终端号唯一，支持设备名称、资产编号、安装地点、所属单位、责任人、SIM 信息和备注。
- 显示固件版本、首次上线、最后在线、最后定位、最后电压、电量和信号。
- 支持按单位、区域、设备组、标签和在线状态筛选。
- 记录注册、鉴权、配置、升级、告警处理和管理员操作审计。
- 未建档设备是否允许自动注册应可配置；生产环境默认进入待审核状态。

## 6. 设备状态

设备状态由通信和定位分别计算，不能混为一个字段：

- 在线：最近收到合法并鉴权的数据。
- 通信告警：超过配置时间未收到数据。
- 离线：超过离线门限。
- 已定位/未定位：取最后一条位置状态。
- 低电量：按百分比规则判断，同时展示原始 VBAT。
- 弱信号：按 CSQ 或后续网络指标判断。

状态门限按设备上报周期动态计算，并允许平台全局默认值、设备组覆盖和单设备覆盖。5 秒设备和 15 分钟设备不能使用同一固定离线时长。

## 7. 告警门限与归属

至少支持：低电量、终端掉电、长时间无通信、长时间未定位、弱信号、越界、异常移动和设备故障。

每条规则包含启停、进入门限、恢复门限、持续时间、重复通知间隔、通知时段、严重等级和适用对象。数值告警必须支持进入/恢复迟滞，防止电压、信号在门限附近反复告警。

归属优先级：单设备规则 > 设备组规则 > 所属单位规则 > 平台默认规则。同一设备同一告警类型同一时段只保留一个活动告警；恢复后记录恢复时间。规则变更必须记录操作人、时间和前后值。

## 8. 短信推送

- 告警进入、持续升级和恢复可分别配置短信模板。
- 收件人来自设备责任人、设备组负责人、所属单位值班人员和指定号码。
- 同一告警事件按事件 ID 去重，不因服务重试重复发送。
- 支持静默时段、频率限制、每日上限和严重告警例外。
- 保存供应商请求 ID、提交时间、回执状态、失败原因和重试次数。
- 短信发送失败不得阻塞设备数据入库；使用独立可靠队列异步执行。

## 9. 性能与可靠性

- 设计容量：10000 台。
- 并发 TCP 连接：不少于 500。
- 单设备补传：最多 512 条一个逻辑批次，并支持连续多个批次。
- 完整批次从接收完成到事务提交并 ACK：P95 小于 2 秒，最大目标 5 秒。
- 接入服务重启不得造成已提交数据重复或未提交数据误确认。
- 数据库定期备份并完成恢复演练；轨迹数据按业务要求分区和归档。

## 10. 安全

- 生产环境启用 TLS，校验服务器证书。
- 每设备独立鉴权码，支持吊销和轮换；禁止把 IMEI 当作秘密。
- 管理端采用角色权限、强密码/多因素认证、登录限流和操作审计。
- 定位、联系人和短信内容属于敏感数据，应最小权限访问、加密存储和按期限清理。
- 密钥、数据库密码和短信凭据只从密钥管理或环境变量加载，不写入仓库。

## 11. 验收测试

至少覆盖注册、鉴权、单条位置、512 条标准分包补传、半包、粘包、转义、校验错误、乱序/重复子包、ACK 丢失、数据库回滚、完全重复及部分重叠批次、断网恢复、500 并发连接、短信去重和告警迟滞。

交付物包括源代码、数据库迁移、API 文档、JT/T 808 对接样例、自动化测试、部署脚本、监控告警说明、压力测试报告和运维手册。
