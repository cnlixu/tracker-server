# 电力定位跟踪器 JT/T 808-2019 接入规范

本项目只接受 JT/T 808-2019 二进制协议，不再兼容 `$PTRK` ASCII 或原自定义 HEX 协议。传输层固定使用 TCP。

## 1. 裁剪后的消息集合

| 方向 | 消息 ID | 用途 |
| --- | ---: | --- |
| 终端→平台 | `0x0100` | 首次注册，获取鉴权码 |
| 平台→终端 | `0x8100` | 注册应答 |
| 终端→平台 | `0x0102` | 每次 TCP 连接建立后的鉴权 |
| 终端→平台 | `0x0002` | 长连接达到配置周期时的心跳 |
| 平台→终端 | `0x8107` | 查询终端属性 |
| 终端→平台 | `0x0107` | 标准终端属性体（启动主动上报／响应查询） |
| 终端→平台 | `0x0200` | 单条实时位置上报 |
| 终端→平台 | `0x0704` | 离线位置批量补传 |
| 平台→终端 | `0x8001` | 鉴权、心跳、属性、参数和位置消息的通用应答 |
| 平台→终端 | `0x8003` | 请求补传指定物理子包 |
| 平台→终端 | `0x8103` | 设置标准参数 `0x0001/0x0002/0x0003/0x0029` |
| 平台→终端 | `0x8104` / `0x8106` | 查询全部／指定终端参数 |
| 终端→平台 | `0x0104` | 查询参数应答 |
| 终端→平台 | `0x0001` | 参数设置通用应答 |

区域路线、电话、文本、多媒体、驾驶员卡、CAN 等消息不属于本产品。设备不为心跳跨上报周期保持TCP连接；只有连续补传使同一连接保持到配置的心跳周期时才发送空消息体 `0x0002`，测试平台返回匹配的 `0x8001`。LOWPOWER/PSM+休眠期间不发送心跳。

## 2. 标准帧

- 起止标识：`0x7E`。
- 2019 版协议版本号：`0x01`，消息体属性 bit14 必须为 1。
- 终端手机号：10 字节 BCD，使用 SIM 对应的真实号码，不允许用 IMEI、IMSI 或 ICCID 替代。不足 20 位时左补零。手机号与固定 SIM 的 ICCID 在产线通过 USB 用户虚拟串口写入终端 FSKV；终端每次启动校验 ICCID，换卡后不得沿用原手机号和鉴权码。
- 多字节整数：大端序。
- 校验：消息头到消息体末字节逐字节 XOR。
- 转义顺序：`0x7D → 0x7D 0x01`，`0x7E → 0x7D 0x02`。
- 单个物理帧消息体最多 1023 字节；超出后使用 JT/T 808 标准分包头。

TCP 是字节流，服务端必须按 `0x7E` 持续拆帧，支持半包、粘包、连续多帧和转义字符，不能把一次 `read()` 当成一帧。

平台下行消息流水号由服务进程统一分配，按 16 位无符号数逐条递增并允许回绕，禁止固定写成 `0`。终端应答必须回显对应的平台流水号和消息 ID；流水号只用于当前交互关联，不承担全局数据去重。

## 3. 注册和鉴权

### 3.1 终端身份及产线写入

生产设备档案应保存终端手机号、ICCID和IMEI三项身份。例如：

| 字段 | 示例 | 要求 |
| --- | --- | --- |
| 终端手机号（MSISDN） | `18508225213` | 必须是当前SIM对应的真实号码，作为JT/T 808终端号 |
| ICCID | `89860064221642652497` | 由设备从SIM自动读取，用于锁卡校验 |
| IMEI | `862288087606784` | 由Air780自动读取，在首次成功鉴权时与终端号绑定 |

手机号必须真实归属于该ICCID。设备无法从运营商网络反查两者的对应关系，只能保证运行时插入的SIM与写号时ICCID一致，所以产线管理系统应负责校验并保存正确映射。服务器以终端手机号为注册主键，以IMEI为唯一设备约束；错误号码或重复号码会造成设备归属错误或鉴权失败。

本项目的 `0x0100` 使用 JT/T 808-2019 标准注册消息体。终端 ID 默认填写 ICCID；IMEI 随 `0x0102` 鉴权上传，完整 ICCID 也会随标准 `0x0107` 终端属性上传。平台仍应保存产线确认过的手机号、ICCID、IMEI 对应关系。终端本地锁卡校验和平台档案校验承担不同职责，不能互相替代。

设备开机后在USB用户虚拟串口 `uart.VUART_0` 开放60秒写号窗口，串口参数为 `115200、8N1`，使用CRLF结尾。产线依次发送：

```text
AT
AT+PHONE=18508225213
```

成功响应：

```text
+PHONE:OK,18508225213,89860064221642652497
OK
```

设备随后自动重启。重启后可发送 `AT+PHONE?` 复核，正确响应为：

```text
+PHONE:18508225213,89860064221642652497
OK
```

写号命令会自动读取ICCID、持久化手机号与ICCID并删除旧鉴权码。服务器不需要人工录入明文鉴权码；设备下一次建立上传连接时重新执行标准注册和鉴权流程。

### 3.2 注册及鉴权流程

设备无本地鉴权码时发送 `0x0100`。测试服务器为本次注册生成独立随机鉴权码，将其 SHA-256 摘要和终端号持久化后，通过成功 `0x8100` 返回明文鉴权码；设备将鉴权码保存到 FSKV。终端重复注册会签发新鉴权码并使旧码失效。

每次 TCP 连接建立后，设备必须先发送 `0x0102`。平台按消息头终端手机号查找注册凭据，校验鉴权码，并在首次成功鉴权时绑定鉴权体内的 15 位 IMEI。终端手机号与 IMEI 是不同字段，不要求数值相同。平台返回成功 `0x8001` 后才允许位置上报。

测试服务器和正式平台都必须为每台设备分配独立鉴权凭据，不能让所有设备共用固定鉴权码。两者是独立系统：本仓库只实现测试服务器，不包含正式后台代码。

### 3.3 标准终端注册消息体

`0x0100` 消息体严格使用 JT/T 808-2019 格式：

| 偏移 | 长度 | 字段 | 说明 |
| ---: | ---: | --- | --- |
| 0 | 2 | 省域 ID | `WORD` |
| 2 | 2 | 市县域 ID | `WORD` |
| 4 | 11 | 制造商 ID | `JZG043`，右补零 |
| 15 | 30 | 终端型号 | `JZG043A`，按标准在左侧补 `0x00` |
| 45 | 30 | 终端 ID | 默认 ICCID，可配置为 IMEI |
| 75 | 1 | 车牌颜色 | 非车辆终端填 0 |
| 76 | 变长 | 车辆标识 | 非车辆终端填 ASCII `0` |

注册体不追加私有 TLV。服务点 ID、资产 ID 和组织归属由正式后台按消息头终端手机号维护，不写入终端。

### 3.4 标准终端属性 `0x0107`

终端在每次 Lua 启动后的首次鉴权成功时主动发送一次标准格式 `0x0107`，同时响应平台空消息体 `0x8107` 查询。该产品约定只改变发送时机，不改变 JT/T 808 消息格式。消息体依次包含终端类型 WORD、制造商 BYTE[5]、型号 BYTE[30]、终端 ID BYTE[30]、ICCID BCD[10]、硬件版本长度和内容、固件版本长度和内容、GNSS 属性 BYTE、通信属性 BYTE。

## 4. 参数配置与 PSM+ 下发

测试服务器通过管理 API `GET/PUT /api/devices/{imei}/configuration` 维护每台终端的期望上报周期。正式后台可采用自己的配置管理方式，但线上消息必须使用标准 `0x8103`。

参数 ID：

| 参数 ID | 类型 | 含义 |
| ---: | --- | --- |
| `0x00000001` | `DWORD` | 终端心跳发送间隔，秒，范围 1～86400 |
| `0x00000002` | `DWORD` | TCP消息首次应答超时，秒，范围 1～3600 |
| `0x00000003` | `DWORD` | TCP消息重传次数，范围 0～10 |
| `0x00000029` | `DWORD` | 缺省时间汇报间隔，秒，范围 5～86400 |

设备在 PSM+ 期间不可达，因此平台不主动建立连接。管理端更新后将配置标为 `pending`；设备下次主动连接并完成 `0x0102` 鉴权后，平台发送 `0x8103`。终端支持上述四个标准参数并进行整组原子校验和持久化，成功后才返回 `0x0001`。当前测试服务器管理API只配置 `0x0029`，正式平台可按需配置其余通信参数。平台用“平台下行流水号 + 被应答消息 ID”匹配应答；断线、超时或失败时在下次连接重发。

配置版本和下发状态是平台内部管理数据，不写入 `0x8103`；TCP重传次数使用标准参数 `0x0003`。修改上报周期不会要求终端重新注册或重新签发鉴权码。

## 5. 位置信息

`0x0200` 的前 28 字节完全使用 JT/T 808-2019 标准位置基本信息：报警标志、状态、纬度、经度、高程、速度、方向和 GMT+8 BCD 时间。

标准附加项：

| ID | 长度 | 内容 |
| ---: | ---: | --- |
| `0x30` | 1 | 蜂窝网络信号强度，当前为 CSQ 0～31 |
| `0x31` | 1 | 参与定位的卫星数 |

本产品只保留 `0xE1` 和 `0xE2` 两个可选制造商自定义附加项；`0xE0` 按标准保留为“后续自定义信息长度”。终端不上传 `generation_id`、`record_seq` 或自定义记录身份，正式平台可以忽略未知附加项。

### 0xE1：电池信息

长度固定 3 字节：

| 偏移 | 长度 | 字段 | 说明 |
| ---: | ---: | --- | --- |
| 0 | 2 | battery_mv | VBAT 毫伏值；`0` 表示未知 |
| 2 | 1 | battery_percent | 0～100；`0xFF` 表示未知 |

电量百分比由终端根据可配置锂电池曲线估算。终端先对多次 ADC 采样取中值，再进行低通和迟滞处理；平台应同时保存毫伏值与百分比，不应使用百分比反推原始电压。

### 0xE2：HDOP

长度固定 1 字节，单位为 0.1；`0xFF` 表示未知。

## 6. 批量补传

离线记录使用标准 `0x0704`：

1. 数据项个数 `WORD`；本产品当前将单个逻辑批次配置为 1～512 条。
2. 位置数据类型 `BYTE`，离线缓存使用 `1`（盲区补报）。
3. 每条记录为 `位置汇报数据体长度 WORD + 0x0200 消息体`。

512 条记录会形成一个逻辑 `0x0704` 消息，再按 1023 字节上限拆成多个标准子包。服务端必须按终端号、消息 ID、消息流水号、总包数和包序号重组，完整校验并解析整批后再入库。

设备支持标准 `0x8003` 补传分包请求：平台给出原消息流水号及缺失包序号后，设备使用原流水号原样补发指定子包。当前本地测试服务器未主动发起 `0x8003`；正式平台可按标准启用，或在未完整重组时不返回成功 `0x8001`，由设备超时重发整批。

`0x8003` 消息体为 `原始消息流水号 WORD + 重传包总数 WORD + N 个包 ID WORD`。终端补发保持原消息 ID、原消息流水号、原总包数和原包序号，不另发 `0x0001`。

## 7. ACK 与可靠性

平台仅在以下动作全部完成后返回成功 `0x8001`：

1. 完整接收并重组逻辑消息。
2. 校验所有物理帧和位置记录。
3. 按平台现有规则写入轨迹点并处理可能的重复位置。
4. 更新设备最新状态。
5. 提交数据库事务。

`0x8001` 必须回显终端消息流水号和消息 ID。结果码采用标准定义：`0` 成功、`1` 失败、`2` 消息有误、`3` 不支持、`4` 报警处理确认。

设备只有收到与当前请求流水号和消息 ID 完全匹配的成功应答，才从 Flash 循环队列删除对应记录。ACK 丢失时设备会重传；测试服务器通过完整位置消息体摘要进行尽力幂等。正式平台不需要解析额外的终端记录 ID。

校验失败或无法信任消息头时不返回 ACK，让终端超时重传。数据库失败返回结果 `1`，消息体错误返回结果 `2`。

## 8. 数据单位

- 坐标：WGS-84，线上单位 `10^-6` 度。
- 高程：米。
- 速度：线上单位 `0.1 km/h`；当前数据库兼容字段仍存储节。
- 方向：0～359 度。
- 时间：JT/T 808 线上为 GMT+8，服务器解析后统一存 UTC。
- VBAT：mV。
- HDOP：0.1。

## 9. 安全边界

JT/T 808 的 XOR 只能检错，不能提供加密、服务器身份认证或防伪造。正式部署应在 JT/T 808 之外启用 TLS，并使用每设备独立鉴权码；敏感定位数据在数据库和备份中也应加密并实施访问审计。
